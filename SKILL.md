## Overview

This skill extends the user's existing workflow (vibecoding, ticket-driven, etc.) by injecting two steps:

1. **Specify** — Capture requirements, analyze for anomalies, ask the user.
2. **Verify** — Generate high-level test design, implement with blind subagents, run tests, fix.

All artifacts are stored under `harmony/features/<feature-name>/` and committed:

- `requirements.md` — human-readable requirements (written by agent, reviewed by user)
- `tests.harmony.md` — high-level test design in `.harmony.md` format (generated by Harmony server)

Test implementations live in the project's normal test folders (e.g. `tests/`, `__tests__/`, `cypress/e2e/`, etc.) — **never** inside `harmony/`.

## Setup

1. Ensure the CLI is available at `<skill-path>/cli/cli.js`.
2. If not authenticated, instruct the user to run:

   ```

   ```

## The Two Steps

### Step 1: Specify

See `steps/01-specify.md` for the full process.

Summary:

- Derive requirements text (workflow-dependent; see `workflows/`).
- Write to `harmony/features/<feature-name>/requirements.md`.
- Run `cli.js analyze` and save result.
- Present anomalies to user as interactive multiple-choice questions (include "Other" and "Not important").
- Update `requirements.md` with clarifications.

For MVP: one analysis turn only (no re-analysis loop).

### Step 2: Verify

See `steps/02-verify.md` for the full process.

Summary:

- Run `cli.js test-design` and save to `harmony/features/<feature-name>/tests.harmony.md`.
- Define the **interface contract** (types, signatures, module boundaries).
- Fire parallel subagents:
  - **Implementor** — receives requirements + interface contract. **Must not read test files.**
  - **Unit Test Writer** — receives `.harmony.md` + interface contract. Writes to normal unit-test folder.
  - **API Test Writer** (if needed) — writes to normal integration-test folder.
  - **E2E Test Writer** (if needed) — writes to normal E2E folder.
- Wait for all subagents.
- Main agent runs tests and fixes failures.

## Workflow Adapters

Pick the appropriate workflow file from `workflows/` before starting Step 1. It tells you:

1. Where the initial requirements come from.
2. How much to infer vs. reuse.
3. Which anomalies are autopilot vs. blocking (for now: all blocking).

## CLI Reference

The CLI is located at `<skill-path>/cli/cli.js`.

```bash
# Authenticate
node cli.js login

# Check health / token
node cli.js status

# Analyze requirements
node cli.js analyze --file harmony/features/auth/requirements.md --out analysis.json

# Generate test design
node cli.js test-design --file harmony/features/auth/requirements.md --out tests.harmony.md
```

Environment variables:

- `HARMONY_API_URL` — override base URL (default: `https://cloud.harmony.ac`)

## Notes

- The agent must **never** expose the auth token in conversation or tool arguments.
- The implementor subagent must be explicitly told: "Do not read files in test directories."
- All `harmony/` files should be committed alongside source code so they live with the project.
